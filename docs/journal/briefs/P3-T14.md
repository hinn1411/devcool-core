# P3-T14 — Presigned PUT upload
P3 · mode A · Should · est 3h · agreed · 2026-11-19

**Why:** `POST /medias/upload` streams every byte through an api task (`MediaController.java:26`, `MediaService.java:76`): a virtual thread and memory for each upload of up to 10 MB. This contradicts `02-tech-stack.md:32` ("API never streams bytes").
**Value:** finishes the phase-3 media design note → the P5 frontend uploads directly to S3 → M1. The scale-to-zero api task stays small (ADR-0013).

## Concepts
- **Signed headers:** without: the client says it's 1 MB but PUTs 500 MB through the URL. With: `Content-Length` and `Content-Type` are in `X-Amz-SignedHeaders`, so any other value gets S3 403. Read: `docs/references/07-aws-compute-edge-networking.md` § S3 presigned URLs.
- **The key is the capability:** without: a member of channel 1 SENDs `channel/2/…/x.png` and channel 1's history points at another channel's object. With: SEND checks the key's shape and its `channelId` against the message's channel. Read: lessons #9.
- **Validate before signing:** without: the server signs `application/pdf` or 0 bytes and S3 accepts it. With: the same `MediaKind` checks as `/upload` run before any port call.

## Done when
1. A member POSTs `/api/v1/medias/presign-upload {channelId, contentType: image/png, size: 1024}` → 200 `{url, key, expiresAt}`. The key matches `OBJECT_KEY_PATTERN` for that channel, the extension comes from the content type, and the TTL is 5 min.
2. Not a member → the existing membership error, no presigner call.
3. Unsupported type, `size ≤ 0`, image over 5 MB, video at 10 MB or more → the existing 4xx exceptions, no port call. Exact limits pass.
4. The adapter signs a PUT with `contentType` and `contentLength`, and `signedHeaders` contains both.
5. A media (IMAGE/VIDEO) SEND whose key doesn't match the pattern or belongs to another channel → `InvalidObjectKeyException`, before any port call, no seq bump.
6. `/upload` still works, shows as `deprecated: true` in OpenAPI, and sends a `Deprecation: true` header.
- **Out of scope:** HEAD/existence check at SEND, cleaning up orphaned uploads (P6), bucket CORS + the frontend switch (P5), POST policy.
- **Tests:** `MediaServiceTest` (1–3, `verifyNoInteractions`), `S3StorageAdapterTest` (4: a real `S3Presigner` with static creds needs no network), `MessageServiceTest` (5), `MediaControllerIT` (1, 2, 6).
- **Files:** `domain/media/port/in/PresignUploadUseCase` + command, `MediaStoragePort.presignPut`, `S3StorageAdapter`, `MediaService` (shared kind/size check), `MediaController` + request/response DTO, the media strategy key check, the tests.
- **Invariants / authz:** membership → validation → presign. A rejected SEND never moves `last_seq`. IAM already grants `s3:PutObject` (`infra/stacks/app/iam.tf:74`).

## Decisions
| Question | Answer | Source |
|---|---|---|
| Size enforcement | Presigned PUT with signed `Content-Length`. The declared size is validated by `MediaKind`, then signed | user; phase design note; SDK `DefaultS3Presigner` (context7) |
| Key check at SEND | Shape + `channelId` == message channel. No S3 call | user; lessons #9 |
| Bucket CORS | Deferred to P5 (no browser client yet) | user |
| PUT URL TTL | 5 min (GET stays at 10) | user |
| Deprecation of `/upload` | `@Operation(deprecated = true)` + `Deprecation` header. Removal after the P5 switch | phase-3 design note |
