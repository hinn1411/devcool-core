# P3-T07 — Delete message (DELETE /messages/{id})
P3 · mode A · Must · est 3h · agreed · 2026-11-11

**Why:** a message can't be removed. History already *hides* soft-deleted rows (`MessageRepository.java:25,40,55`, P3-T05), but ADR-0012:42 says a deleted message keeps its seq and shows as "message deleted".
**Value:** phase goal "Edit/delete". Unblocks P4-T04 (WS `DELETE` → `MESSAGE_DELETED`), P6-T02 (`MessageDeleted` → S3 cleanup, reindex), P5-T05 (deleted state).

## Concepts
- **Tombstone, not filter:** without: a client holding seq 41 never learns it was deleted, and 40→42 looks like lost data. With: history returns seq 41 with `content=null` and `deletedTime`, and the client shows "message deleted".
- **Don't reuse the channel-admin policy:** without: `ChannelPermissionPolicy.allows` is true for every LOUNGE member (`ChannelPermissionPolicy.java:29`), so anyone could delete anyone's message. With: an explicit rule: the sender, a LOUNGE/FORUM CREATOR, or a FORUM LEADER.
- **Idempotent conditional UPDATE:** `UPDATE … SET deleted_time=? WHERE id=? AND deleted_time IS NULL`. 0 rows = already deleted, still 204. The first timestamp wins.
- **Load includes deleted rows:** without: reusing `findForEdit`, which excludes deleted rows, gives a repeat delete 404. With: a separate load that keeps deleted rows, so the repeat gets 204.

## Done when
1. Sender deletes → 204. The row stays, with `deleted_time = now(clock)`.
2. A LOUNGE/FORUM CREATOR or a FORUM LEADER deletes another member's message → 204.
3. A member who is neither → 403 (including a PRIVATE_CHAT creator on the other person's message). Non-member or unknown id → 404.
4. Repeat delete → 204, `deleted_time` unchanged. Two concurrent deletes → both 204, one timestamp (IT).
5. History (`beforeSeq`, `afterSeq`, the `cursorId` alias) returns a deleted message as a tombstone: same seq and sender, `content` and media null, `deletedTime` set.
6. Editing a deleted message → 404 (already true; keep the test).
- **Out of scope:** the WS frame (P4-T04), S3 removal and the event (P6-T02), undo, hard delete or legal erase, `deleted_by`.
- **Tests:** `DeleteMessageServiceTest` (authz matrix × channel type, idempotent repeat); `MessageAdapterIT` (conditional update, tombstones in all 3 queries; replaces `softDeletedMessage_isExcluded`); a concurrency IT; `MessageControllerTest` (204/403/404); `MessageDtoMapperTest` (tombstone nulls).
- **Files:** `DeleteMessageUseCase` + command, the service, `MessagePort` (load incl. deleted + `markDeleted`), `MessageRepository`, `MessageAdapter`/mapper, `MessageItem` + response (`deletedTime`), `MessageController`.
- **Invariants / authz:** load incl. deleted (404) → member (404) → sender, LOUNGE/FORUM CREATOR or FORUM LEADER (403) → conditional UPDATE.

## Decisions
| Question | Answer | Source |
|---|---|---|
| Deleted in history | Tombstone (seq kept, content/media null, `deletedTime`) | ADR-0012:42; phase Design notes |
| Success response | 204, also on repeat | user |
| Admin delete scope | CREATOR in LOUNGE/FORUM, LEADER in FORUM (the only type with one, `ForumCreationStrategy`); DM: sender only | user; Green |
| Who deleted | Not stored; P6-T02 event carries the actor | user |
| Window | None: delete any time | phase Design notes |
