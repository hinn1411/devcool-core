# P3-T00 — Channel update validation per type
P3 · mode A · Should (unlisted debt) · est 2h · done · 2026-10-26

**Why:** `ChannelService.java:71-85` writes any name/type/expiry the caller sends, so a member can turn a DM into a FORUM with an expiry, or set a lounge expiry 1 minute ahead.
**Value:** P3 goal "role-based channel management". A stable type is what P3-T11 (leader transfer) and P3-T12 (unique DM pair) rely on. Unblocks `docs/learning/13-integration-testing-exercises.md` exercise 7.

## Concepts
- **Domain policy vs service check:** without → rules live in `ChannelService` and can only be tested with mocks. With → a pure `ChannelUpdatePolicy` next to `ChannelPermissionPolicy`, one plain JUnit test per rule. Read: `docs/references/01-architecture-hexagonal-modular-monolith.md` § Concepts to own.
- **Transition rules need current state:** without → the command alone can't tell "change type" from "same type". With → reuse the `ChannelAccessInfo` that `requireAllowed` already returns (discarded at `ChannelService.java:72`).
- **Injected Clock:** without → "7 days ahead" tests depend on wall time and flake at the boundary. With → a `Clock` bean (none exists today), so tests pin `now`.

## Done when
1. Given any channel, when the update sends a `channelType` ≠ the current type → `InvalidChannelConfigException` (400), nothing written.
2. Given a PRIVATE_CHAT or FORUM, when an `expiredTime` is sent → rejected.
4. Given a lounge expiring in 3 days, when the body has only `name` → renamed, type and expiry kept.
3. Given a LOUNGE (update or create), when `expiredTime` ≤ now + 7d → rejected; null or > now + 7d → saved.
- **Out of scope:** removing an expiry (a missing field keeps the stored value), type changes and their leader/size side effects (forbidden for now), member roles (P3-T11).
- **Tests:** `ChannelUpdatePolicyTest` (one per rule, boundary at exactly 7d, happy paths); `ChannelServiceTest` verifies `channelPort.update` is never called on rejection; `LoungeCreationStrategyTest` covers the expiry rule on create; `ChannelControllerTest` checks 400 and a name-only body; `ChannelControllerAuthzIT` checks that a rename-only PATCH keeps the type and expiry (COALESCE on real Postgres).
- **Files:** `domain/channel/policy/ChannelUpdatePolicy.java`, `application/service/channel/ChannelService.java`, `application/service/channel/strategy/LoungeCreationStrategy.java`, a `Clock` `@Bean` config, tests.
