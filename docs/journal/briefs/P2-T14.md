# P2-T14 — patch backend dependencies before the first deploy
P2 · mode C · Must · est 3h · done · 2026-10-20

**Why:** the image ships Boot 3.5.6 (`pom.xml:8`) and `nimbus-jose-jwt` 9.37 (`pom.xml:160`), with 50 fixable HIGH/CRITICAL library CVEs ([P2-T06 brief](P2-T06.md) Decisions). `ci-docker.yml:75-85` gates only `vuln-type: os`, so they pass CI → P2-T04's smoke deploy would put them on the public `dev-cool.click`, and P2-T08's `deploy.yml` scan ("fail on HIGH/CRITICAL with fix") would block every deploy.
**Value:** a patched first image for P2-T04's smoke deploy → M1. Unblocks P2-T04 (rebase + push), P2-T08 (deploy scan passes). Dependabot keeps it patched afterwards.

## Concepts
- **Fixable vs unfixed gate:** without: gating every HIGH/CRITICAL fails on CVEs that have no patch yet → CI stays red and teams learn to ignore it. With: `ignore-unfixed: true` gates only what a bump can fix; the report step still lists the rest. Read: ref 09 Concepts (Supply chain).
- **BOM-managed versions:** without: pinning `tomcat-embed-core` or `spring-webmvc` by hand drifts from what Boot tested. With: bump the Boot parent and let its BOM move Framework 6.2.19, Tomcat 10.1.55, Jackson, Netty together; pin only what Boot doesn't manage (`nimbus-jose-jwt`). Read: `pom.xml:5-10`.
- **Expiring ignores:** without: a `.trivyignore` line hides a CVE forever, even after 3.5.x backports the fix. With: `.trivyignore.yaml` entries carry `statement` + `expired_at`; on expiry the gate fails and forces a re-check. Read: Trivy docs, "Filtering → .trivyignore.yaml".
- **Dependabot groups:** without: one PR per dependency each week, or a surprise Boot 4 major. With: one grouped minor/patch PR a week; parent majors ignored until a Boot 4 task/ADR. Read: `.github/dependabot.yml`.
