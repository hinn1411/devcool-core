# P3-T13 — Keyword search (per channel + across my channels)
P3 · mode A · Should (per channel) / Could (global) · est 5 h · agreed · 2026-11-17
**Why:** history is keyset-only (`MessageController.java:52`): finding an old message means scrolling every page; no text index on `message.content` (`V1__baseline.sql:83`).
**Value:** server side of the P5-T11 search box (→ M3); keyword half of P8 hybrid search (`02-tech-stack.md:33`, RRF later).

## Concepts
- **Generated `tsvector` + GIN:** without: `content ILIKE '%deploy%'` scans every message row. With: words split once on write; GIN maps word → rows. Read: refs/05 § Full-text search.
- **`websearch_to_tsquery`:** without: `to_tsquery('fix bug')` throws on raw input → 500. With: never a syntax error; `"phrase"`, `or`, `-word` work.
- **Soft-delete leak:** delete keeps `content` (`DeleteMessageService.java:62`). Without `deleted_time IS NULL` in the query a deleted message still matches and leaks its text.
- **Hit → context:** each result carries `seq`; the client opens it via `?afterSeq=seq-k` (P3-T05).

## Done when
1. Given a member and `q` matching words, when `GET /channels/{id}/messages/search?q=`, then live TEXT/MARKDOWN matches of that channel with `seq`, newest first.
2. Non-member or missing channel → same answer as history (`ChannelAuthorizer.requireMember`).
3. Blank `q` or > 200 chars → 400, no DB query.
4. Deleted and media-only messages are never returned.
5. Operators/junk in `q` (`"((`, `-`, `&!`) → 200, maybe empty, never 500.
6. `GET /messages/search?q=` returns matches only from channels the caller is a member of now; a left channel (P3-T11) is excluded.
7. Paging: `limit` 1–100 + `hasMore`; cursor `beforeSeq` (channel) / `beforeId` (global).
- **Out of scope:** semantic/hybrid (P8), search UI (P5-T11), prefix/as-you-type, stemming, `ts_headline` snippets.
- **Tests:** unit: service authz-first + validation. IT: FTS match, case-insensitive, no stemming (`simple`), deleted excluded, junk input, global membership filter, paging. Negative authz: non-member → 403.
- **Files:** `V10__message_search.sql`, native query in `MessageRepository` (JPQL has no `@@`), `MessagePort.search*`, search query port + command + service, `MessageController`, DTO + mapper.
- **Invariants / authz:** membership check before the FTS query; global search filters membership in the same SQL, never in Java afterwards.
