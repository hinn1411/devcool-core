# P3-T03a — Number NULL seqs and set message.seq NOT NULL (contract)
P3 · mode A · Must · est 2h · agreed · 2026-11-07

**Why:** V4 left `message.seq` nullable (`V4__message_seq_and_read_state.sql:1-2`). Rows inserted by old (pre-T03) tasks from the V4 deploy (2026-10-27) until the T03 rollout finishes have a NULL seq → history by seq (P3-T05) and RESUME skip them, and nothing stops a future NULL.
**Value:** closes the P3-T02 expand/contract → phase goal "Ordering" ([ADR-0012](../../plans/architecture/adr/0012-message-ordering-per-channel-seq.md)) → M2. Unblocks P3-T05, T10, P4 RESUME.

## Concepts
- **Contract only after every writer is new:** without: V5 ships while a pre-T03 task is live → its seq-less insert fails NOT NULL. With: V5 merges after the T03 deploy succeeded, so every running task writes seq. Read: `.claude/rules/flyway.md`.
- **Append, don't renumber:** without: re-run `row_number()` over all rows → existing seqs move, and a client that saw seq 7 now gets another message. With: NULL rows get `last_seq + row_number() over (partition by channel_id order by id)`. Read: ADR-0012.
- **Same lock order as a send:** without: number the rows, then bump `last_seq` → a live send in between takes the same seq → unique violation. With: bump `channel.last_seq` first (row lock until commit) and number from the old value. Read: ref 05 § Concepts (row locks).
- **SET NOT NULL scans under ACCESS EXCLUSIVE:** fine for smoke data with `lock_timeout`. On a big table: `CHECK (seq IS NOT NULL) NOT VALID` → `VALIDATE` → `SET NOT NULL` (PG12+ skips the scan) → drop the check. Read: `docs/learning/11-flyway-and-schema-management.md` §7e.

## Done when
1. Given channel A with seqs 1..3 (`last_seq` 3) and two NULL-seq rows, when V5 runs, then those rows get 4 and 5 in id order, `last_seq` = 5, and the existing seqs don't change.
2. Given a channel with no NULL rows, when V5 runs, then its `last_seq` and `last_message_at` are unchanged.
3. Given V5, an insert with a NULL seq is rejected.
- **Precondition:** the P3-T03 deploy succeeded on dev before this merges (run 42353404364).
- **Out of scope:** dropping V2's `(channel_id, id DESC)` index (after P3-T05); batching (dev has only smoke data).
- **Tests:** `V5ContractIT` in the style of `V4BackfillIT`: `migrateTo("4")` → seed with JDBC → migrate → assert 1–3. Then `./mvnw -Dit -Pstatic-analysis verify`.
- **Files:** `db/migration/V5__message_seq_not_null.sql`, `src/test/java/com/devcool/V5ContractIT.java`, `MessageEntity.seq` (`@Column(nullable = false)`), phase file tick.
