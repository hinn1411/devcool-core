# P1-T02 — Local DB on `pgvector/pgvector:pg16`, credentials out of git
P1 · mode A · Must · est 2 h · done · 2026-10-02

**Why:** local runs `postgres:15` (`docker/local/compose.yaml:3`) while ADR-0009 fixes PG 16 with pgvector for Aurora and Testcontainers. The DB password is committed in three places: `compose.yaml:6`, `compose.yaml:38` (pgAdmin) and `application-local.properties:8`.
**Value:** first step of the schema group → P1 Definition of Done (`phase-1` `:99`). Unblocks P1-T01 (baseline generated on PG 16), P1-T11 (same image in Testcontainers) and P8's `CREATE EXTENSION vector`.

## Concepts
- **Compose service connection matches by image name:** without: Spring Boot 3.5.6 only recognises `postgres` and `bitnami/postgresql`, so after the image change it silently falls back to the credentials in the properties file. With: a `org.springframework.boot.service-connection: postgres` label keeps the auto-wiring. Read: Spring Boot docs, "Docker Compose support".
- **Major versions don't share a data directory:** without: PG 16 starts on the PG 15 volume and exits with an incompatible-files error. With: `docker compose down -v` first; safe because no data exists (ADR-0009 Consequences).
- **Extension files vs enabling:** without: on `postgres:15`, `CREATE EXTENSION vector` fails in P8. With: the image ships the files; enabling stays a Flyway migration (ADR-0009).
- **Fail loudly on missing config:** without: a fresh clone with no `.env` starts Postgres with an empty or default password. With: `${POSTGRES_PASSWORD:?…}` stops compose with a clear message.

## Done when
1. `SELECT version()` on the local DB reports PostgreSQL 16, and `vector` appears in `pg_available_extensions`.
2. `git grep` finds the DB password and the pgAdmin password in no tracked file; `docker/local/.env` is ignored by git.
3. `application-local.properties` has no datasource url, username or password; the app on the `local` profile connects through the compose service connection, from a fresh volume.
4. Without an `.env` file, `docker compose up` fails with a message naming the missing variable; a committed `.env.example` lists every variable with placeholder values.
5. pgAdmin still opens the database, with its credentials taken from the same `.env`.
- **Out of scope:** `CREATE EXTENSION vector` (P8); Flyway and `ddl-auto=validate` (P1-T01); Testcontainers (P1-T11); rewriting git history for the old throwaway password.
- **Tests:** manual, by command: the two SQL checks, `git grep`, `git check-ignore docker/local/.env`, an app start on `local`, and `docker compose config` with and without `.env`.
- **Files:** `docker/local/compose.yaml`, `docker/local/.env.example` (new), `docker/local/.env` (new, ignored), `docker_pgadmin_servers.json` (removed), `application-local.properties`, phase file checkbox.
- **Invariants / authz:** no credential value in any tracked file; `.env` is the single source for the local DB and pgAdmin credentials.

## Prediction gaps
- (a) "centralize the creds" → the driver is that the password is committed in three places, including the properties file (*knowledge gap*: `11-security.md` §Secrets).
- (b) "it can connect" → it also connects with the password still in git, or via the silent properties fallback; the criteria rule both out (*knowledge gap*: Spring Boot docs, "Docker Compose support").
- (c) "container shows pgvector 16" → ask the server (`SELECT version()`), and prove the secret is gone with `git grep` (*knowledge gap*).
- (d) 30 min → about 2 h: the service-connection label, pgAdmin and the missing-`.env` behaviour are the real work.
