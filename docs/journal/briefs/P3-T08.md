# P3-T08 — Replies (reply_to_id + reply preview)
P3 · mode A · Could · est 4h · done · 2026-11-12

**Why:** a message can't point at another one. `03-chat-system-design.md:42,66` plans `message.reply_to_id`; no migration, entity field or `WsClientFrame` field exists (`WsClientFrame.java:5`).
**Value:** phase goal "Replies and reactions". Unblocks P5-T05 (reply preview), P5-T07 (composer reply); P8-T02 `ChunkBuilder` keeps reply links.

## Concepts
- **Parent in the same channel, not "caller is a member":** without: Bob replies in his channel with `replyToId` = a message from a private DM, and the history preview leaks the DM (BOLA). With: the parent row must have `channel_id = command.channelId`. Read: ADR-0012, `03 §12`.
- **One error, no oracle:** without: distinct errors for not found / other channel / deleted let a caller probe ids. With: all three → NACK `MESSAGE_400` "Invalid replyToId".
- **Replay before the parent check:** without: retrying a reply whose parent was deleted meanwhile is rejected, though the original was saved. With: the parent is checked in `saveOnce` after `findReplay` (`MessageService.java:93`), so the retry gets `duplicate=true`.
- **Live preview via a join:** without: a lazy `replyTo` → N+1 per page, or a stored copy goes stale on edit/delete. With: `LEFT JOIN FETCH ms.replyTo rt LEFT JOIN FETCH rt.user` in the 3 history queries; a deleted parent shows as a tombstone.

## Done when
1. SEND without `replyToId` → `reply_to_id = NULL`; the history item has `replyTo = null`.
2. SEND with a live parent in the same channel → `reply_to_id` saved; history returns `replyTo {id, seq, senderId, senderName, contentType, preview, deleted}`; `preview` = TEXT/MARKDOWN content cut to 100 chars, null for media.
3. Parent unknown, in another channel, or deleted → NACK `MESSAGE_400`, nothing saved, `last_seq` not bumped.
4. Parent deleted after the reply → history still returns the reply, `replyTo.deleted = true`, `preview = null`.
5. Retry (same `clientMsgId`) after the parent was deleted → `duplicate=true`, no NACK.
6. The live WS `MESSAGE` push carries `replyToId` (null when not a reply).
7. All 3 history queries load a page of replies in one SQL statement (no N+1).
- **Out of scope:** threads / reply count, changing `replyTo` on edit, the full `MESSAGE_NEW` preview (P4-T04), hard delete / FK `ON DELETE` (P6).
- **Tests:** `MessageServiceTest` (valid, unknown, other channel, deleted, retry after delete); `WsSendMessageServiceTest` (`replyToId` in push); `MessageAdapterIT` (preview per query, deleted parent, statement count); `MessageDtoMapperTest`; the migration via the existing ITs.
- **Files:** `V6__message_reply_to.sql`, `MessageEntity`, `MessagePort`/adapter, `MessageRepository`, `MessageMapper`, `MessageItem` + `ReplyPreview`, `MessageItemResponse`, `WsClientFrame`, `SendMessageCommand`, `CreateMessageCommand`, `MessageService`, `WsSendMessageService`.
- **Invariants / authz:** membership (existing) → replay → parent live and in the same channel (400) → bump + insert, in one transaction.

## Decisions
| Question | Answer | Source |
|---|---|---|
| Reply to a reply | Allowed; flat, one level of preview | design §2 self-FK |
| Index on `reply_to_id` | None: reads join the parent by PK, nothing hard-deletes | P3-T07 |
| Preview content | Server snippet ≤100 chars; media → null + contentType | user |
| Bad `replyToId` error | One `MESSAGE_400` for unknown / other channel / deleted | user |
| WS push | Add `replyToId` to `OutboundWsEvent` now | user |
| Deleted reply | Tombstone quotes nothing (`replyTo = null`); rules in domain `ReplyPreview.of` | review |
