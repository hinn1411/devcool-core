# P1-T05 — No secrets in exception details
P1 · mode A · Must · est 1 h · done · 2026-10-01

**Why:** `PasswordIncorrectException.java:9` and `PasswordNotMatchException.java:9` store the submitted password in `details`, and `ApiExceptionHandler.java:25-31` copies `details` into the response body (audit #2, `docs/learning/README.md:22`).
**Value:** closes audit row #2 → P1 Definition of Done ("every Open row fixed, with a test"). Unblocks P1-T07 (change-password is the natural thrower of both exceptions) and P1-T17.

## Concepts
- **Error bodies are output too:** without: a user mistypes their old password on change-password → the response carries `details.password` in plaintext. With: the body has code `USR_223` and an empty `details`. Read: `docs/references/11-security.md` §Concepts.
- **Secrets leak through copies, not the wire:** without: the echoed password lands in ECS logs, APM traces (P7), browser HAR files and frontend error toasts. With: it only ever exists in the request. Read: `docs/learning/02-security-and-authorization.md:55-90`.
- **Make the unsafe call impossible:** without: the constructor takes a `String`, so the next caller passes the password. With: a no-arg constructor, so the compiler rejects it.

## Done when
1. `PasswordIncorrectException` and `PasswordNotMatchException` have no-arg constructors and empty `details`.
2. `grep -rn 'Map.of("password"' src/main/java/com/devcool/domain/` returns nothing.
3. Given `POST /api/v1/auth/login` with a wrong password, the error body does not contain the submitted password anywhere.
- **Out of scope:** change-password itself (P1-T07); username enumeration via `UserNotFoundException` (`learning/02` §4); `handleGeneric` exposing the exception class name; a reflective guard over all domain exceptions (revisit with ArchUnit, P1-T13).
- **Tests:** unit: both exceptions have empty details; `ApiExceptionHandlerTest`: the body's details are empty for each; `@WebMvcTest` slice on login: send a known password, assert the response text does not contain it (you write this assertion first).
- **Files:** `domain/auth/exception/Password{Incorrect,NotMatch}Exception.java`, `ApiExceptionHandlerTest.java`, new `src/test/.../controller/AuthControllerTest.java`, new exception unit test, phase file checkbox.
- **Invariants:** details carry identifiers and constraints, never submitted secrets (`.claude/rules/hexagonal.md`).
