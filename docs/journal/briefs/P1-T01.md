# P1-T01 — Flyway `V1__baseline.sql`, `ddl-auto=validate` everywhere
P1 · mode A · Must · est 4 h · done · 2026-10-03

**Why:** `local` builds the schema with `ddl-auto=update` (`application-local.properties:9`) and `ecs` validates against no migrations (`application-ecs.properties:7,10`) → a fresh Aurora DB can never boot (audit #8).
**Value:** P1's migration-managed schema → M1 (running on ECS). Unblocks P1-T03 (V2 index), P1-T11 (Flyway smoke IT), P2-T05/T08 (migrate task), P3-T01 (BIGINT), P8-T01 (`CREATE EXTENSION vector`).

## Concepts
- **Schema as an append-only log:** without: `update` adds but never drops/renames, so local and Aurora drift silently. With: every env replays the same `V1..Vn`. Read: `docs/references/05-postgresql-and-data-access.md` "Migrations as code".
- **`validate` checks shape, not rules:** tables, columns, types, sequences only; names and CHECKs are ignored → a new enum value with a stale CHECK fails on first insert, not at boot. Read: `docs/learning/11-flyway-and-schema-management.md` §5c.
- **Pooled sequences:** bare `SEQUENCE` expects `<table>_seq` with `INCREMENT BY 50`; `BY 1` → Hibernate 6 refuses to start. Read: `11-…` §5a.
- **Baseline vs `baseline-on-migrate`:** the old local volume → "non-empty schema". `down -v` proves V1 builds everything; `baselineOnMigrate` marks V1 applied without running it and hides the bug. Read: `11-…` §5f.

## Done when
1. Given an empty DB (`docker compose down -v`), when the app boots on `local`, then Flyway logs `V1` applied and `validate` passes.
2. Given an entity column renamed on purpose, when the app boots, then it fails on `validate` (revert after).
3. `spring.jpa.generate-ddl` is removed (`application.properties:5`); every profile uses `ddl-auto=validate`; Flyway is on in default/`local` and off in `ecs`.
4. V1: one `_seq` per table `INCREMENT BY 50`, lowercase unquoted names, no redundant `UNIQUE` on PKs, current `integer` ids, all 9 entities' tables.
5. Every FK/UK/CHECK has a readable name (`fk_channel_creator`, `uk_email`, `ck_member_role`), and FK/UK names match `@ForeignKey`/`@UniqueConstraint` in the entities.
6. `pom.xml` has `flyway-database-postgresql` (Flyway 10+ split Postgres out of `flyway-core`; context7).
- **Out of scope:** BIGINT ids (P3-T01), migrate profile/task (P2-T05), automated IT (P1-T11), `CREATE EXTENSION` (P8-T01), `refresh_token.user_id` varchar-vs-integer mismatch.
- **Tests:** manual boot checks 1 and 2; P1-T11 automates them.
- **Files:** `src/main/resources/db/migration/V1__baseline.sql`, `application{,-local,-ecs}.properties`, `pom.xml`, `adapters/out/persistence/**/entity/*.java`, `CLAUDE.md:111-112`, phase file (P1-T01 wording + checkbox).
