# P4-T03 — PING/PONG heartbeat, 90 s server idle close
P4 · mode B · Must · est 3 h · agreed · 2026-11-26

**Why:** v2 `PING` gets `NACK{UNSUPPORTED}` (no handler, `FrameDispatcher.java:69-72`); only v1 answers (`PingAction.java:28`). No idle timeout is set (`WebSocketConfig.java:23-28`) → a half-open socket (laptop sleeps) stays in `SessionRegistry` with all its subscriptions; server pushes keep the ALB hop busy (120 s, `infra/stacks/app/alb.tf:14`), so the ALB never closes it either.
**Value:** Stage 1 hardening (`learning/10` §7) → M2. Unblocks T10 (presence TTL refreshed on `PING`, 03 §8), T14 drain, P5-T06 (client heartbeat every 25 s).

## Concepts
- **App-level PING:** without: the browser can't send protocol pings, so the client can't tell a dead socket from a quiet channel. With: `PING` every 25 s; a missing `PONG` → reconnect. Read: `references/03` § Frames and control frames.
- **Read-idle, not any-idle:** without: pushes to a dead laptop count as activity, the socket never expires. With: only *client* frames reset the clock → closed ~90 s after the last one. Read: Tomcat `READ_IDLE_TIMEOUT_MS`.
- **Timeout ladder:** 25 s heartbeat < 90 s server idle < 120 s ALB idle: one lost PING doesn't kill a live socket, and the server closes before the ALB. Read: `references/03` self-check 3, 03 §10.

## Done when
1. A v2 `PING` with a `reqId` → exactly one `PONG{reqId}`; the socket stays open.
2. A v2 `PING` without `reqId` → `NACK{INVALID}` (dispatcher unchanged); it still resets the idle clock.
3. Any client frame (v1, v2, invalid) resets the idle clock.
4. No client frame for `devcool.ws.idle-timeout` (default 90 s) → server closes with 1001; registry entry and every subscription cleaned up via the existing `cleanUp` (`ChatHandler.java:150-159`).
5. A connection that only receives pushes, no client frames, still closes on time.
6. v1 `PING` behaviour unchanged.
- **Out of scope:** presence refresh on PING (T10), client heartbeat (P5-T06), server-initiated PING, frame metrics (T15), Valkey (T05).
- **Tests:** `PingHandlerTest` (1); `SessionRegistryTest` (idle property set on the native session); `WsHeartbeatIT` with idle timeout 2 s + Awaitility (1, 2, 4, 5: close code 1001 and no further pushes).
- **Files:** `handler/v2/PingHandler`, `SessionRegistry.bound()`, idle-timeout prop (`WsSendLimitsProps` or new `WsIdleProps`), `application.properties`.
- **Invariants:** an idle close is not a frame error (ADR-0005 rule 2 holds); cleanup runs on this exit path too (`websocket-protocol.md` last rule).

## Decisions
| Question | Answer | Source |
|---|---|---|
| What resets the clock | Any client frame | phase file line 52 ("without frames") |
| Who sends PING | Client only, every 25 s | 03 §10 |
| Mechanism | Tomcat `READ_IDLE_TIMEOUT_MS` per session in `SessionRegistry.bound()`; no `@Scheduled` sweeper (closes 90 s + up to Tomcat's background-check period) | user; tomcat-embed-websocket 10.1.46 |
