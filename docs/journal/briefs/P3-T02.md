# P3-T02 — Seq, idempotency and read-state columns (expand)
P3 · mode A · Must · est 3h · agreed · 2026-10-27

**Why:** `message` has no per-channel order and no idempotency key (`V1__baseline.sql:84-96`). History pages by id (`MessageRepository.java:21`). The WS frame already carries `clientMsgId` (`WsClientFrame.java:10`), but nothing stores it → a retry duplicates the message, and clients can't detect gaps.
**Value:** P3 goal: ordering, idempotent send, edit and read state ([ADR-0012](../../plans/architecture/adr/0012-message-ordering-per-channel-seq.md), [03 §2](../../plans/architecture/03-chat-system-design.md)). Unblocks P3-T03 (seq, clientMsgId), T05 (history by seq), T06 (version), T10 (last_read_seq), and P4 `RESUME`.

## Concepts
- **Expand/contract:** without: `seq NOT NULL` in V4 → old tasks, and this image too, insert without a seq → every send fails during rollout. With: `seq` nullable now, counters get `DEFAULT 0`, NOT NULL comes in P3-T03a. Read: `.claude/rules/flyway.md`.
- **Window-function backfill:** without: numbering old messages later → they can only get seqs above the new ones, so the order breaks. With: `row_number() over (partition by channel_id order by id)` in V4, then `last_seq = max(seq)`. Read: ADR-0012 § Consequences.
- **The unique index doubles as the history index:** without: a separate `(channel_id, seq DESC)` → a second index to update on every insert. With: Postgres scans the `(channel_id, seq)` btree backwards for `ORDER BY seq DESC`. Read: ref 05 § Keyset pagination.
- **Locks are held until commit:** without: forgetting that Flyway runs V4 in one transaction → the ACCESS EXCLUSIVE lock from `ADD COLUMN` lasts through the backfill, and sends queue behind it. With: smoke data takes milliseconds, and `lock_timeout 5s` as in V3. Read: `docs/learning/11-flyway-and-schema-management.md` §7e.

## Done when
1. Given messages in two channels before V4, when V4 runs, then seqs are 1..n per channel in id order, `channel.last_seq` = n, `last_message_at` = the latest `created_time`, and `member.last_read_seq` = the channel's `last_seq`. A channel with no messages gets 0 and NULL.
2. Given V4, a second row with the same `(channel_id, seq)` or `(user_id, client_msg_id)` is rejected. Two NULL `client_msg_id`s from one user are allowed.
3. Given old tasks running, when V4 applies, then they keep sending (no new NOT NULL without a default). The old image still starts, because validate ignores unmapped columns, so unlike V3 a rollback works.
- **Columns:** `channel.last_seq bigint not null default 0`, `channel.last_message_at timestamptz`, `message.seq bigint`, `message.client_msg_id uuid`, `message.version integer not null default 0`, `member.last_read_seq bigint not null default 0`.
- **Out of scope:** seq assignment and idempotent send (P3-T03); re-backfill plus `SET NOT NULL` (P3-T03a); dropping V2's `(channel_id, id DESC)` (after P3-T05's alias goes); renaming `user_id` → `sender_id` (never: it breaks old tasks).
- **Tests:** `V4BackfillIT`: a fresh database in the shared container, Flyway `target("3")` → seed via JDBC → migrate → assert criteria 1–2. `DevCoolApplicationIT`: history includes 4. Then `./mvnw -Dit -Pstatic-analysis verify`.
- **Files:** `db/migration/V4__message_seq_and_read_state.sql`, the new IT, `DevCoolApplicationIT`, the phase file (P3-T02 line, new P3-T03a).

## Decisions
| Question | Answer | Source |
|---|---|---|
| Separate `(channel_id, seq DESC)` index? | No: `UNIQUE (channel_id, seq)` serves it | user; phase line updated |
| Move `version` / `last_read_seq` to T06 / T10? | No: every expand change goes in V4 | user |
| Where does the seq backfill go? | V4, before P3-T03 numbers new messages | user; ADR-0012 |
| Who does the contract step? | New task P3-T03a, after P3-T03 is deployed | user; phase file |
| `last_read_seq` start for existing members | `channel.last_seq` (history counts as read) | user |
| `sender_id` or `user_id`? | Keep `user_id`: a rename breaks old tasks | `V1__baseline.sql:86` |
| Map the columns in the entities now? | No, in the tasks that use them (a `ChannelEntity.lastSeq` without `0L` would insert NULL) | validate ignores unmapped columns |
| Batch the backfill? | No, one statement: dev holds only smoke data | flyway rules (batch large tables) |
