# P3-T06 — Edit message (PATCH /messages/{id})
P3 · mode A · Must · est 3h · agreed · 2026-11-10

**Why:** a sent message can never change: `MessageController` is GET-only, there is no `EditMessageUseCase`, `MessageEntity` doesn't map V4's `version` (`V4…sql:14`), and `MessageItem` has no `version`/`editedTime` → a client has no expected version to send.
**Value:** phase goal "Edit/delete". Unblocks P4-T04 (`EDIT` frame → this use case → `MESSAGE_UPDATED`) and P5-T07 (edit UI). Interview #13 (`delivery-book/08:50`).

## Concepts
- **Stale client vs in-flight race:** without: the phone edits v0→v1, the laptop (still showing v0) edits; `@Version` load→save reloads v1 and overwrites silently. With: `UPDATE … SET content=?, version=version+1, edited_time=? WHERE id=? AND version=:expected` → 0 rows → 409; one statement also covers the concurrent race. Read: ref 05 § Optimistic concurrency.
- **Exists → allowed → act, no oracle:** without: a non-member gets 403 for `/messages/999` → learns that it exists. With: missing/deleted/non-member → the same 404; member but not the sender → 403 (`.claude/rules/hexagonal.md`).
- **Time windows need a Clock:** without: `Instant.now()` → the 24h boundary can't be tested. With: inject the `Clock` bean (`ClockConfig.java:12`), and tests pin 24h−1s and 24h.

## Done when
1. The sender, current `version`, < 24h: content replaced, `version+1`, `editedTime=now(clock)`, 200 with the updated item.
2. `version` ≠ current → 409, the row is unchanged. IT: a stale client; two concurrent edits on v0 → exactly one 200.
3. `createdTime + 24h ≤ now` → 403 `MESSAGE_EDIT_WINDOW_CLOSED`; at 24h−1s → 200.
4. IMAGE/VIDEO → 4xx. Content blank, > 1000 code points, or containing NUL → 4xx (the P3-T15 rules, reused not copied).
5. Same content as now (and current version) → 200, no bump, `editedTime` unchanged.
6. A member but not the sender → 403. A non-member, unknown id, or deleted message → 404.
7. History items carry `version` and `editedTime` (null if never edited).
8. `content` and `version` are required: a missing one → 4xx (`@Schema` says there's one field to edit, so ADR-0014 "missing = keep" doesn't apply).
- **Out of scope:** the WS `EDIT` frame and `MESSAGE_UPDATED` (P4-T04), edit history/audit, changing contentType, delete (P3-T07).
- **Tests:** `EditMessageServiceTest` (Mockito + fixed Clock: rules 1, 3–6); `MessageAdapterIT` (conditional update: stale and concurrent); `MessageControllerTest` (PATCH 200/403/404/409/4xx); `MessageDtoMapperTest` (version, editedTime).
- **Files:** `domain/chat/port/in/EditMessageUseCase` + command, the service, `MessagePort` (find for edit + `updateContent(id, expected, content, editedTime)` → rows), `MessageEntity.version`, `MessageRepository`, `MessageController`, request/response DTOs + mapper, `MessageItem`, `ErrorCode` + `HttpErrorMapper`, a shared content-validation policy.
- **Invariants / authz:** check order: load (404) → membership (404) → sender (403) → type → window (403) → content → version/no-op → conditional update (409).

## Decisions
| Question | Answer | Source |
|---|---|---|
| Expected version transport | Body field `version` (shared with P4 WS `EDIT`) | user |
| Window closed | 403 `MESSAGE_EDIT_WINDOW_CLOSED`; 409 is only for version conflicts | user |
| Editable fields | `content` only, required | user; ADR-0014 noted |
| Unchanged content | No-op: 200, no bump; the version is still checked first | user |
| Non-member / unknown / deleted | 404, the same answer for all | hexagonal rules (no oracle) |
| Lock style | Conditional UPDATE on the client's version, not `@Version` load→save | phase Design notes; concept 1 |
