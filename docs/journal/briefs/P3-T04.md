# P3-T04 — Outbound WS event carries messageId, seq, createdTime
P3 · mode A · Must · est 1.75h · agreed · 2026-11-09

**Why:** the MESSAGE push has only type/channelId/senderId/contentType/content (`WsSendMessageService.java:40-46`), and the sender's ACK is just `"SENT"` (`RawWebSocketHandler.java:108-111`) → clients can't order, dedupe or reference a pushed message, though ADR-0005 rule 3 and design §5 require all three fields.
**Value:** phase goal "Ordering" + "Idempotent send" (phase DoD) → M2. Unblocks P4 RESUME/gap detection, P4-T04 (EDIT/DELETE by messageId), P3-T10 (`PUT /read {seq}` sends a seq the client saw).

## Concepts
- **Fields from the DB, not the request:** without: build the event from the command + `Instant.now()` → the push's createdTime differs from history's and there's no seq. With: take them from `SavedMessage` (the committed row). Read: design §3.
- **seq = ordering + gap detection:** without: a client holding seq 7 receives 9 → silently misses 8. With: 9 ≠ 7+1 → `RESUME {lastSeq: 7}` (P4). Read: ADR-0012, design §4 Recovery.
- **messageId = dedupe + mutation key:** without: after a reconnect the history page and the push overlap → the message renders twice. With: the client merges by messageId. Read: design §5 rules.
- **Retry re-ACK:** without: the sending tab is skipped by the push and its ACK has no ids → its own message has no seq until reload. With: the ACK carries the original messageId/seq, even for a duplicate. Read: design §4 table row 1.

## Done when
1. Given a new send, when it's pushed to the channel's other connections, then the payload has `messageId`, `seq`, `createdTime` equal to `SavedMessage`'s.
2. Given a new send, when the sender gets its ACK, then the ACK data carries the same `messageId`, `seq`, `createdTime`.
3. Given a retried clientMsgId, then nothing is pushed and the ACK carries the original ids.
- **Out of scope:** v2 envelope, `MESSAGE_NEW` rename, moving `OutboundWsEvent` into `adapters/in/websocket/dto` (P4-T02).
- **Tests:** `WsSendMessageServiceTest` (ArgumentCaptor on the emitter payload; returned SavedMessage: 1, 3); `RawWebSocketHandlerTest` (ACK JSON has the ids, createdTime ISO-8601: 2, 3).
- **Files:** `WsSendMessageService`, `SendMessageUseCase` (returns `SavedMessage`), `RawWebSocketHandler`, both tests.

## Decisions
| Question | Answer | Source |
|---|---|---|
| Field names | `messageId`, `seq`, `createdTime`; keep `type: "MESSAGE"` | ADR-0005 rule 3; rename is P4-T02 |
| createdTime wire format | ISO-8601 UTC string (Spring's ObjectMapper, same as REST history) | `WsRealtimeEmitterAdapter` injects Boot's mapper |
| ACK carries the ids (incl. retry re-ACK) | Yes, in this task | user; design §4 |
