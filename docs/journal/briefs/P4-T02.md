# P4-T02 — Protocol v2 envelope, dispatcher, per-frame errors
P4 · mode B · Must · est 5–6 h · agreed · 2026-11-26

**Why:** v1 has no `reqId` (`SendMessageAction.java:42` replies `ERROR{clientMsgId:null}`), errors are free text, and only `DomainException` is caught (`ChatHandler.java:110-119`) → any other exception closes the socket with 1011 (`learning/04` §7).
**Value:** Stage 1 hardening (`learning/10` §7) → M2. Unblocks T03 `PONG`, T04 `EDIT`/…, T09 `RESUME`, T12 `TYPING`, T13 `NACK RATE_LIMITED`, T14 `RECONNECT`, T17, P5-T06 typed client, P8 `ASK`.

## Concepts
- **reqId correlation:** without: 2 SENDs in flight, one fails → `ERROR{null}`, which one? With: `NACK{reqId:"c-18"}` marks only that one. Read: ADR-0005 decision drivers.
- **NACK codes:** without: the client string-matches `"MEMBER_404"`. With: `FORBIDDEN` → drop the channel; `INTERNAL` → retry the same `clientMsgId` (idempotent). Read: `ws-protocol` skill.
- **Catch-all boundary:** without: a mapper NPE on SEND → 1011, and the user leaves every channel. With: `NACK INTERNAL`, other subscriptions keep flowing. Read: `learning/04` §7.
- **Tolerant reader + version gate:** unknown fields ignored; unknown `v` → close 4400 so an old tab reloads. Read: ADR-0005 rules 4–5.

## Done when
1. Given a v2 `SUBSCRIBE`/`UNSUBSCRIBE`/`SEND` with a `reqId` → exactly one `ACK` with that `reqId`; SEND ACK = `{clientMsgId, messageId, seq, createdTime}`.
2. Unknown or not-yet-built type (PING→T03, EDIT→T04, …) → `NACK{UNSUPPORTED}`; unknown fields are ignored.
3. Bad payload (no `channelId`, bad `clientMsgId`/`contentType`) → `NACK{INVALID}` with the `reqId`.
4. A reply-needing v2 frame without `reqId` → `NACK{INVALID, reqId:null}`; the action does not run.
5. `DomainException` → `NACK{code mapped from ErrorCode, message: domain code}`; non-member `SUBSCRIBE` → `NACK{FORBIDDEN}`.
6. Any `RuntimeException` in a handler → `NACK{INTERNAL}`, logged; the socket stays open and the next frame works.
7. Unparseable JSON → `ERROR{INVALID}`; the socket stays open.
8. `v` missing or 1 + flag on → the v1 path is unchanged; flag off or `v` ≥ 3 → close 4400.
9. A connection whose latest frame was v2 gets `MESSAGE_NEW{messageId, seq, createdTime, …}`; a v1 connection keeps `MessagePush`.
- **Out of scope:** PING/PONG (T03), new frame types (T04/T09/T12), rate limits (T13), frame metrics (T15), v1 removal (T17), frontend (P5-T06).
- **Tests:** `FrameDispatcherTest` (1–7), `NackCodeMapperTest` (exhaustive), `ChatHandlerTest` (8), `SessionEmitterAdapterTest` (9), `WsProtocolV2IT` (1, 5, 6, 9 end to end); `AbstractWsIT` helpers migrated to v2.
- **Files:** `websocket/dto/v2/**`, `handler/FrameDispatcher` + `FrameHandler`, NACK code mapper, `WsProtocolProps`, `SessionEmitterAdapter`, `AbstractWsIT`.
- **Invariants / authz:** no frame-level error closes the socket; commit → ACK → publish is unchanged; the `SUBSCRIBE` membership check stays in the service.

## Decisions
| Question | Answer | Source |
|---|---|---|
| ErrorCode → NACK code | Exhaustive switch like `HttpErrorMapper` (403→FORBIDDEN, 404→NOT_FOUND, 409→CONFLICT, 400/422→INVALID) | `HttpErrorMapper.java` |
| Unknown fields | Ignored (Boot `ObjectMapper` default) | ADR-0005 rule 4 |
| ERROR vs NACK | `ERROR` only when no envelope parses; otherwise `NACK` | `ws-protocol` skill |
| Push format | Per connection, from the latest frame's `v` | user |
| v1 flag | `devcool.ws.protocol.legacy-v1-enabled=true`; off → close 4400 | user, ADR-0005 rules 2, 5 |
| No `reqId` | `NACK{INVALID}`, action not run | user, ADR-0005 rule 1 |
| IT helpers | Migrate `AbstractWsIT` to v2; one v1 case kept for the flag | user |
