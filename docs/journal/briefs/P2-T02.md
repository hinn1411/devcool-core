# P2-T02 — network stack (VPC, egress, security groups)
P2 · mode C · Must · est 2–3 h · agreed · 2026-10-15

**Why:** `infra/stacks/` has only `bootstrap`, so there are no subnets or SGs → P2-T03 (Aurora subnet group + SG) and P2-T04 (ALB, tasks) cannot be applied, and nothing deploys.
**Value:** the first layer of the walking skeleton → M1 (a merge deploys to dev). Unblocks P2-T03, P2-T04, P2-T09 (hibernate turns egress off), P4 Valkey SG, P8 Bedrock endpoint.

## Concepts
- **Public vs private subnet:** without: Aurora gets a public IP and the internet can reach it if one SG rule is loosened. With: a private subnet has no IGW route, so the DB has no internet path at all. Read: [learning 17](../../learning/17-terraform-in-devcool.md) §network.
- **SG chained by SG id:** without: Aurora allows `10.0.0.0/16:5432`, so anything in the VPC reaches the DB. With: `sg-aurora` allows only `sg-api`. Read: [ref 07](../../references/07-aws-compute-edge-networking.md) §VPC and networking.
- **An egress path for private tasks:** without: NAT and endpoints both off while tasks run → `CannotPullContainerError`, the task never starts. With: both are on while awake and off only when `app` is destroyed. Read: [learning 18](../../learning/18-docker-and-ecs.md) §ECS networking.
- **A toggle that changes only what it owns:** without: NAT and endpoints bill hourly while hibernated. With: setting `enable_nat=false` and `enable_interface_endpoints=false` → the plan deletes only NAT, EIP, routes and endpoints. Read: [ref 08](../../references/08-terraform-iac.md) §Concepts.

## Done when
1. Given a dev apply, a second `plan` shows no changes (no drift).
2. Given `enable_nat=false` and `enable_interface_endpoints=false`, `plan` deletes only NAT, EIP, the NAT route and the interface endpoints; VPC, subnets, SGs and the S3 gateway endpoint stay.
3. Given the SGs, `sg-api` :8080 accepts only `sg-alb`, `sg-aurora` :5432 accepts only `sg-api`, `sg-vpce` :443 accepts only `sg-api`; no task or DB has a public IP.
4. Subnet, VPC and SG ids are published as SSM parameters for `data` and `app`.
- **Out of scope:** Aurora (P2-T03), ALB/ECS (P2-T04), CloudFront (P2-T07), the `env-power` workflow that flips the toggles (P2-T09), VPC flow logs, Valkey/worker SGs (P4/P6).
- **Tests:** CI `ci-infra` (fmt, validate, tflint, Trivy; picks up the new stack automatically); `plan` reviewed by `aws-architect`; criteria 1–2 run by hand in an AWS window.
- **Files:** `infra/stacks/network/*.tf`, `infra/envs/dev.tfvars`, `infra/envs/dev.backend.hcl`.
- **Invariants:** turn both toggles off only when `app` is destroyed (hibernate); with tasks running, both are on.

- (b) missed the SG chain and the no-public-IP invariants (*knowledge gap*: ref 07 §VPC and networking).
