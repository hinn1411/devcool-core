# P3-T05 — History API by seq (beforeSeq / afterSeq)
P3 · mode A · Must · est 3h · agreed · 2026-11-09

**Why:** history pages by `id < cursorId` (`MessageRepository.java:15-27`), while clients hold `seq` (push + ACK since P3-T04) → no "older than seq 41" or "everything after seq 41" (ADR-0012:8). `cursorId` is also returned when `hasMore=false` (`MessageService.java:151`, docs/learning/05 §10).
**Value:** phase goal "Ordering" → M2. Unblocks P4 RESUME/RESYNC REST fallback (design §4 Recovery, §10), P3-T09 (counts per page), P3-T07 (tombstones in history).

## Concepts
- **Keyset on seq, not id:** without: V5 gave rollout NULL-seq rows seqs after `last_seq` → id order ≠ seq order, an id cursor skips/repeats vs the push. With: `seq < :beforeSeq ORDER BY seq DESC` = push order. Read: ADR-0012:35-36, `V5__message_seq_not_null.sql`.
- **Two directions:** without: reconnect at seq 41 → reload newest page, 42..60 lost. With: `afterSeq=41` → `seq > 41 ORDER BY seq ASC`. Read: design §4 Recovery row.
- **Keyset is stable under inserts:** without: OFFSET page 2 shifts when a message arrives → duplicate. With: the seq bound doesn't move. `UNIQUE(channel_id, seq)` (`V4…sql:45`) serves both directions (`EXPLAIN`). Read: ref 05 § Keyset, :42, :85.

## Done when
1. Given seq 1..5 and `beforeSeq=4&limit=2`, then items seq 3, 2; `hasMore=true` (next call: `beforeSeq=2`, the last item's seq).
2. Given `afterSeq=2&limit=2`, then items seq 3, 4; `hasMore=true` (next call: `afterSeq=4`).
3. Given no cursor, then the newest `limit` messages, DESC. Every item carries `seq`; soft-deleted rows stay excluded.
4. Given exactly `limit` remaining, then `hasMore=false` and the deprecated `cursorId` is null.
5. `cursorId` still works (deprecated in Swagger). Two cursors in one request (`beforeSeq`+`afterSeq`, or a seq param + `cursorId`) → 400.
6. Bad input (`limit` 0/101, `beforeSeq<1`, `afterSeq<0`) → 4xx, never 500.
7. Non-member → existing membership error; missing channel → 404.
- **Out of scope:** tombstones (P3-T07), reaction counts (P3-T09), dropping `ix_message_channel_id_id` (with the alias removal).
- **Tests:** `MessageAdapterIT` (both directions, deleted, other channel); `MessageServiceTest` getMessages (hasMore, cursorId null, cursor rules); `MessageControllerTest` WebMvc (5–7); `MessageDtoMapperTest` (seq).
- **Files:** `MessageController`, `GetMessageCommand`, `MessageService`, `MessagePort`, `MessageAdapter`, `MessageRepository`, `MessageItem`, `MessageList`, `MessageItemResponse`, `GetMessagesResponse`, `MessageDtoMapper`.
- **Invariants / authz:** `requireMember` before any read (`MessageService.java:140`).

## Decisions
| Question | Answer | Source |
|---|---|---|
| Order | beforeSeq/none → DESC; afterSeq → ASC | ADR-0012:35-36 |
| Limit / bounds | default 20, 1..100; `beforeSeq ≥ 1`, `afterSeq ≥ 0` | `MessageController.java:34`; seq starts at 1 |
| Two cursors at once | 400, mutually exclusive | user |
| Deleted messages | still excluded; tombstones in P3-T07 | user |
| `cursorId` | deprecated alias for one phase | user; phase file :48 |
| Next cursor | no field: next bound = last item's seq (exclusive, so no ±1); `cursorId` kept, null when !hasMore | user; seqs have gaps (ADR-0012:42) |
