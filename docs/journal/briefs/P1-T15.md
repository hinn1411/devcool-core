# P1-T15 — Structured JSON logging + WS MDC
P1 · mode C · Must · est 2h · agreed · 2026-10-09

**Why:** Logs are plain text everywhere. In CloudWatch (`awslogs`), a stack trace becomes one event per line and logs can't be queried by field. WS lines (e.g. `WsSubscribeService.java:35`) don't say which connection they came from. `spring.jpa.show-sql=true` (`application.properties:5`) prints raw SQL to stdout in every profile (`docs/learning/01-jpa-and-transactions.md:219`).
**Value:** M1 (P2 ECS deploy) has queryable logs from day one. Base for P7-T03 log→trace correlation (ADR-0008) and P4 WS work.

## Concepts
- **Structured log:** without: "errors for user 42" means grepping message text, which misses differently worded lines. With: `userId=42` is a field, so one query finds every line. Read: `docs/references/10-spring-boot-and-java-runtime.md` §Concepts.
- **MDC lifecycle:** without `clear()`: a pooled Tomcat thread keeps user A's ids, so user B's next frame is logged as A. With: set in `try`, clear in `finally` around each callback. Read: ref 10 (SLF4J MDC link).
- **MDC is per thread:** without propagation: a send handed to an executor (P4 fan-out) logs with no ids. With: a copy-and-restore wrapper. Not needed in P1; noted for P4.

## Done when
1. Given profile `ecs`, when the app logs, then every stdout line is one ECS JSON object, including stack traces.
2. Given profile `local`, then logs stay human-readable text.
3. Given a WS frame, connect or close, when anything logs during that callback, then `userId` and `connectionId` are fields. After the callback the MDC is empty, even if the callback threw.
4. `show-sql` leaves `application.properties`; `local` logs SQL via `logging.level.org.hibernate.SQL=DEBUG`.
- **Out of scope:** HTTP MDC (`userId` in `JwtAuthFilter`), custom `requestId` (P7 OTel `trace.id` covers it), MDC across executors (P4), log shipping (P7-T03).
- **Tests:** unit: MDC holds the ids during the delegate call and is empty after, also on exception. IT (`StructuredLoggingIT`): under `ecs`, a log line with MDC set and an exception parses as one JSON line with `userId`; under the default profile it stays text.
- **Files:** `application{,-ecs,-local}.properties`, `adapters/in/websocket/config/WebSocketConfig.java`, new `adapters/in/websocket/handler/MdcWebSocketHandlerDecorator.java`, tests.

## Decisions
| Question | Answer | Source |
|---|---|---|
| Where MDC is set | A `WebSocketHandlerDecorator` around `RawWebSocketHandler`, covering all 4 callbacks | `WebSocketConfig.java:21` |
| JSON format | Built-in `logging.structured.format.console=ecs`, no new dependency | ADR-0008:31, Spring Boot 3.5 |
| HTTP MDC / requestId | WS only, as the phase file says. HTTP correlation comes from the P7 `trace.id` | user, ADR-0008 |
| Mode | C: Claude writes, user reviews | `delivery-playbook.md` §2 (observability → C) |
| SQL logging in `local` | Logger, not `show-sql`: `show-sql` prints to `System.out`, so it skips the log format and levels | implementation |
| Logging IT setup | `StructuredLoggingIT` boots an empty context with the real `ecs` profile, so no DB or Testcontainers base. The WS path is proven by the decorator unit test | implementation |
