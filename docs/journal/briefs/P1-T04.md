# P1-T04 — `UserController` returns a DTO, not `User`
P1 · mode A · Must · est 1.5 h · done · 2026-10-01

**Why:** `UserController.java:25` serializes the domain `User`, so any logged-in user can walk `/api/v1/users/1..N` and download every bcrypt hash and `tokenVersion` (`docs/learning/README.md:21`, audit #1).
**Value:** closes audit row #1 → P1 goal "security holes closed" → P1 Definition of Done. Feeds P1-T12 (profile JSON shape IT), P1-T17, game day #2 (`delivery-playbook.md:230`) and interview Q12 (`:431`).

## Concepts
- **Response DTO is an allowlist (OWASP API3):** without: someone adds `resetToken` to `User` → it ships in the JSON the same day. With: only fields declared on the DTO serialize. Read: `docs/references/11-security.md` §Concepts.
- **Assert on the wire, not the type:** without: the test checks the return type; someone adds `password` to the DTO → still green. With: a MockMvc test asserts the `password` and `tokenVersion` keys are absent from the JSON → red.
- **BOLA on the remaining fields:** without: reusing `GetProfileResponse` hides the hash but still lets anyone enumerate every email, role and status. With: a public-fields DTO for other users; `/auth/profile` keeps the full view for self.
- **Ports are the domain's front door:** the controller importing `GetUserQuery` is correct hexagonal; the bug is returning the model past the adapter (`.claude/rules/hexagonal.md`).

## Done when
1. Given a valid token, when `GET /api/v1/users/{id}`, then the body's data contains exactly `id`, `username`, `name`, `avatar`, with no `password`, `tokenVersion`, `email`, `role`, `status` or `lastLoginTime` key.
2. `UserController` return type is `ApiSuccessResponse<UserProfileResponse>`, mapped by `UserDtoMapper` with `unmappedTargetPolicy = ERROR`.
3. Unknown id still returns the existing `UserNotFoundException` mapping.
4. The test runs in `./mvnw test` (no database), so CI catches a regression today.
- **Out of scope:** full-stack profile IT on Testcontainers (P1-T12, phase test plan `:94`); `permitAll` clean-up (P1-T09); ArchUnit rule (P1-T13); ownership check (not needed for public fields); hiding blocked or deleted users (P3).
- **Tests:** `@WebMvcTest` slice for `UserController` with `GetUserQuery` mocked, asserting on the Jackson output (you write the first failing assertion); `UserDtoMapperTest` in the style of `AuthDtoMapperTest`.
- **Files:** `adapters/in/web/controller/UserController.java`, new `dto/response/UserProfileResponse.java`, new `dto/mapper/UserDtoMapper.java`, `src/test/.../controller/UserControllerTest.java`, `src/test/.../dto/mapper/UserDtoMapperTest.java`, phase file checkbox.
- **Invariants / authz:** any authenticated user may read another user's public fields; private fields are served only by `/api/v1/auth/profile` for the caller.

## Prediction gaps
- (a) "domain leak in controller" → it is a security hole first: password hashes are downloadable (*knowledge gap*: `docs/learning/02-security-and-authorization.md:11-38`).
- (b) "controller imports nothing from domain" → it must import the inbound port; the invariant is about the JSON (*knowledge gap*: `docs/architecture-request-flow.md`).
- (c) "check the DTO type" → a type check can't catch a sensitive field added to the DTO; assert on serialized JSON (*knowledge gap*: `docs/learning/06-testing-and-verification.md:171`).
- (d) 15 min → the code is 15 min; mode A means you write the failing test first, plus DTO, mapper and mapper test: about 1.5 h.
