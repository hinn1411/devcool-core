# P3-T16 — UNSUBSCRIBE wired end to end
P3 · mode A · Must · est 3–4 h · done · 2026-11-20

**Why:** an `UNSUBSCRIBE` frame falls to `default` → `ERROR "Unsupported action"` (`RawWebSocketHandler.java:122`), and `WsUnsubscribeService` is empty. Also, remove/leave (`MemberManagementService.java:48,69`) leave the user's sockets subscribed, and fan-out (`WsSendMessageService.java:39`) doesn't check membership → a removed member keeps getting live messages.
**Value:** completes the v1 action set (ADR-0005) and closes a push-side authz leak → M1. Unblocks P4-T02 (dispatcher handler) and P4-T08 (ref-counted unsubscribe, ADR-0006).

## Concepts
- **Connection-scoped vs user-scoped state:** without it, unsubscribe also drops `connectionId → userId` → the next SEND on that socket has no user. With it, unsubscribe touches only `channel → {connIds}`; close (`:136`) does the rest. Read: learning/10 §7.
- **Server-derived identity:** without it, a frame carries `connectionId` → user A unsubscribes user B's tab. With it, `connectionId = session.getId()`.
- **Authz on the push path:** without it, Bob is removed from a Forum, but his open tab still shows new messages. With it, remove/leave also unsubscribes all of Bob's connections from that channel, and SUBSCRIBE's `requireMember` stops him re-joining.

## Done when
1. A subscribed connection sends `UNSUBSCRIBE {channelId}` → `ACK` with its `clientMsgId`, and no more pushes from that channel (IT).
2. Also subscribed to B: unsubscribing A keeps B pushes and SEND working.
3. Not subscribed / not a member → `ACK`, no-op.
4. No `channelId` → `ERROR "Missing channelId"`, socket stays open.
5. The use case gets `session.getId()`, never a frame value.
6. Admin removes Bob, or Bob leaves → each of Bob's connections stops getting that channel's pushes (IT: Bob subscribed in 2 tabs).
- **Out of scope:** v2 envelope/NACK (P4-T02), backplane ref-count and the cross-node `chat:user:{id}` "removed" event (P4-T08), the SUBSCRIBE-vs-remove race (P4).
- **Tests:** `WsUnsubscribeServiceTest`, `RawWebSocketHandlerTest` (ACK, missing channelId, server connId), `InMemoryConnectionRegistryAdapterTest` (`unsubscribeUser`), `MemberManagementServiceTest` (remove/leave call it; a failed authz doesn't), `WsUnsubscribeIT` (Done 1, 2, 6).
- **Files:** `RawWebSocketHandler`, `WsUnsubscribeService`, `UnsubscribeCommand(connectionId, channelId)`, `ConnectionRegistryPort` + `InMemoryConnectionRegistryAdapter` (`unsubscribeUser(userId, channelId)`), `MemberManagementService`.
- **Invariants / authz:** UNSUBSCRIBE needs no membership check, since it only shrinks your own subscriptions. Unsubscribe the user only after the remove/leave authz passes.

## Decisions
| Question | Answer | Source |
|---|---|---|
| Not subscribed / not a member | ACK, no-op | registry no-ops (`InMemoryConnectionRegistryAdapter.java:43`) |
| Missing `channelId` | ERROR frame, socket open | user; matches the SEND error path (`:108`) |
| Removed member still pushed | fixed in this task; unsubscribe runs after commit | user; review: before commit a SUBSCRIBE still sees the row |

## Prediction gaps

- Server receives `userId, connectionId` from the frame → only `channelId` comes from the frame (*knowledge gap*: Concept 2).
- IT for the flow → agreed, plus unit tests (*plan issue*: IT added).
