# P1-T07 — Change password, end to end
P1 · mode A · Must · est 3 h · done · 2026-10-02

**Why:** `AuthController.java:140-144` returns `null` (an empty 200) and `UserAdapter.updatePassword` returns `false`, so a user is told their password changed when nothing was written (audit #6, `docs/learning/02-security-and-authorization.md` §5).
**Value:** closes audit row #6 → P1 Definition of Done. First real user of the no-arg exceptions from P1-T05; P5's settings screen depends on it.

## Concepts
- **Fail closed:** without: the stub answers 200, and the user believes a leaked password was rotated. With: the endpoint either changes the password or returns an error. Read: `learning/02` §5.
- **Revocation on credential change:** without: an attacker's access token (1 h) and refresh token (14 days) survive the change, because `RefreshTokenService.refresh` never checks `tokenVersion`. With: `tokenVersion` is bumped and the user's refresh tokens are deleted in the same transaction. Read: `docs/references/11-security.md` §Concepts.
- **Salted hashes can't be compared:** without: a test asserts `hash(new) == stored` and always fails, because bcrypt salts each hash. With: assert `hasher.matches(raw, stored)`.
- **Identity comes from the token:** without: a `userId` in the body lets Alice change Bob's password. With: the id comes from `Authentication` only.

## Done when
1. Given the correct current password, the new hash is stored, `tokenVersion` is bumped, all of the user's refresh tokens are deleted, the response is 204 and the `rt` cookie is expired.
2. Given a wrong current password, the response is 422 `USR_223`, nothing is written, and the body contains neither password.
3. `confirmedPassword` ≠ `newPassword` → 422 (`PasswordNotMatchException`); new = current → 422 (`PASSWORD_DUPLICATE`).
4. `ChangePasswordUseCase.change(ChangePasswordCommand)` returns `void`; the caller id comes from `Authentication`.
- **Out of scope:** rate limiting on wrong attempts (P4/P9); password-strength rules beyond `@Size`; keeping the current device signed in; a DB round-trip IT (needs P1-T11).
- **Tests:** `UserServiceTest.Change` rewritten for the command and the new outcomes (you write the first test per behaviour); a controller slice (204 + expired cookie, caller id from the principal, 422 without echo); `HttpErrorMapperTest` row for `PASSWORD_INCORRECT`; adapter queries stay unverified until ITs exist.
- **Files:** `ChangePasswordUseCase`, new `ChangePasswordCommand`, `UserService`, `UserPort`/`UserAdapter`/`UserRepository`, `AuthController`, `AuthDtoMapper`, `HttpErrorMapper`, new `PasswordDuplicateException`, tests, phase file checkbox.
- **Invariants / authz:** password, `tokenVersion` and refresh-token deletion change in one transaction or not at all; no password value appears in logs, exceptions or responses.
