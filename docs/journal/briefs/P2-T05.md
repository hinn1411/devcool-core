# P2-T05 — ecs datasource from secrets + migrate profile
P2 · mode C · Must · est 2h · done · 2026-10-14

**Why:** `ecs` turns Flyway off, but nothing runs migrations on ECS → the first deploy fails `validate` ([learning/README #8](../../learning/README.md)).
**Value:** the migrate step for P2-T08's deploy → M1. Also fixes the env/secret names for P2-T04.

## Concepts
- **One-off migrate task:** without: a bad migration crashes every new api task mid-rollout. With: it runs once before the service update; exit ≠ 0 stops the deploy. Read: [phase-2 §Database migrations](../../plans/phases/phase-2-infra-cicd-walking-skeleton.md).
- **Secrets injection:** the task def's `secrets` turn the RDS secret's username/password into env vars at start; the URL stays plain env. Read: [ref 07](../../references/07-aws-compute-edge-networking.md).
- **Profile composition:** `ecs,migrate`: migrate only overrides web=none + Flyway on, and reuses ecs's datasource.
- **Expand/contract:** old tasks run on the new schema during a rolling deploy. Read: [.claude/rules/flyway.md](../../../.claude/rules/flyway.md).

## Done when
1. `ecs,migrate`: Flyway migrates, Hibernate validates, no port opens, exit 0.
2. A failing migration → exit ≠ 0.
3. `ecs` alone: no Flyway; datasource from env (username/password from the RDS secret).
4. `local` and existing ITs unchanged.
- **Out of scope:** task def wiring (P2-T04), run-task + exit-code check (P2-T08), Dockerfile (P2-T06), secret rotation (P2-T03 carry-over).
- **Tests:** `MigrateProfileIT` (happy path + broken migration); manual `java -jar … ; echo $?`.
