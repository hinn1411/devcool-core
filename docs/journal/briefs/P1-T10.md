# P1-T10 — Health probes and graceful shutdown
P1 · mode A · Must · est 2h · agreed · 2026-10-09

**Why:** no actuator in `pom.xml`, and `SecurityConfig.java:38` has no health path in its allowlist. In P2, the ALB check (`phase-2:61`) and the deploy smoke test (`phase-2:85`) would get 404/401, so ECS would replace every task and the deploy circuit breaker would roll back.
**Value:** the "Health endpoints" item of the P1 goal; a prerequisite for M1 (running on ECS behind the ALB). Unblocks P2-T08 (deploy) and P4-T14 (WS drain).

## Concepts
- **Probe = kill switch on ECS:** without: a DB check in the probe, an Aurora failover, all 3 tasks fail at once, ECS replaces them all, every user is disconnected. With: the probe checks only the JVM; HikariCP reconnects once the DB is back after 60 s. Read: [learning/14](../../learning/14-health-checks-and-graceful-shutdown.md) §3–4.
- **Readiness follows the lifecycle:** without: a stopping task still answers 200. With: on SIGTERM it goes `REFUSING_TRAFFIC` and returns 503. Read: ref 10, "Liveness vs readiness".
- **Graceful shutdown:** without: a deploy cuts a media upload halfway (5xx). With: up to 30 s to finish it. Works only because `Dockerfile:13` uses an exec-form `ENTRYPOINT`, so Java is PID 1 and receives SIGTERM. Keep it that way in P2-T06.

## Done when
1. Given no token, when GET `/actuator/health/liveness` or `/actuator/health/readiness`, then 200 `{"status":"UP"}` with no `components`.
2. Given the app publishes `ReadinessState.REFUSING_TRAFFIC`, when GET `/actuator/health/readiness`, then 503.
3. Given any other actuator path (e.g. `/actuator/env`), then it is not exposed: 401 without a token, 404 with one.
4. Both probe groups stay at Spring's defaults: no `db` or other external indicator (learning/14 §4).
5. `server.shutdown=graceful` and `spring.lifecycle.timeout-per-shutdown-phase=30s` are set (config only; no test, by decision).
6. P4-T14 gets a one-line note: ECS deregisters before SIGTERM, so revisit the drain order (`01-system-architecture.md` §4.5, `phase-2:61`).
- **Out of scope:** the WS drain and `RECONNECT` (P4-T14); ALB/ECS timings (P2); metrics and Prometheus exposure (P7).
- **Tests:** `HealthEndpointIT` extends `AbstractIntegrationTest`, covering criteria 1–3. The criterion-2 test must restore `ACCEPTING_TRAFFIC` afterwards, because the context is cached and shared across ITs.
- **Files:** `pom.xml`, `application.properties`, `SecurityConfig.java`, `src/test/java/com/devcool/adapters/in/web/HealthEndpointIT.java`, `docs/plans/phases/phase-4-*.md` (note only).
