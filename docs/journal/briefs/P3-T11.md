# P3-T11 — Member management: remove, leave, transfer leader
P3 · mode A · Must · est 5 h · done · 2026-11-16

**Why:** members could only be added (`ChannelAction`); a kicked or departing user kept access and a Forum couldn't change leader.
**Value:** finishes P3 role-based management → M1. P4 relies on removed users failing SUBSCRIBE/RESUME; P3-T12 on a DM keeping both members.

## Concepts
- **Hard delete, keep content:** a soft-deleted row blocks `uk_member_channel_user` (V1:79) on re-add; deleting it keeps messages and lets a re-add start caught up.
- **Lock before checking:** parallel adds read a stale count and break the 11-person cap; `requireAllowedForUpdate` (`FOR NO KEY UPDATE`) keeps checks true until commit. Read: refs/05 § row locks.
- **One leader:** the Forum leader can't leave or be removed until they transfer; transfer swaps roles and `leader_id` in one transaction.
- **Authz on every path:** a removed user gets 403/404 on every channel service (`ChannelAuthorizer`). Read: `lessons.md` membership rule.

## Done when
1. A Lounge creator or Forum creator/leader removes a MEMBER → 204, row gone, count −1, messages kept.
2. Other roles → 403; PRIVATE_CHAT → 400; removing the creator, the Forum leader or self → 400; non-member target → 403.
3. A member leaves → 204, count −1. Forum leader or PRIVATE_CHAT → 400; non-member → 403.
4. The Forum leader transfers to a member → target LEADER, old LEADER → MEMBER (a CREATOR stays CREATOR), `leader_id` = target.
5. Transfer by a non-leader → 403; to self → 400; to a non-member → 403; non-Forum → 400.
6. A removed user is rejected on every channel path.
- **Out of scope:** dropping a live WS subscription (P4), creator transfer, member list.
- **Tests:** `MemberManagementServiceTest`, `ChannelPermissionPolicyTest`, `ChannelControllerAuthzIT`, `MemberManagementConcurrencyIT`.
- **Invariants:** one leader per Forum; `total_of_members` = row count; checks run 404 → 403 member → 400 unsupported → 403 role.
