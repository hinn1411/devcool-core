# P4-T04 — v2 EDIT/DELETE/REACT/READ frames + live events
P4 · mode B · Should · est 6.5 h · agreed · 2026-11-26

**Why:** only `SendMessageService.publish` fans out; the P3 edit/delete/reaction/read services never call `RealtimeEmitterPort`, so changes reach others only on refetch. v2 answers these 4 types with `NACK UNSUPPORTED` (`FrameDispatcher.route`).
**Value:** phase goal protocol v2 → M2; closes P3-T06/T07/T09/T10 deferrals. Unblocks P5-T05/T07/T09 (live edit/delete/reaction/read UI), T07/T08 (these events cross the backplane).

## Concepts
- **Commit → publish:** without: an edit broadcasts inside `@Transactional`, commit fails, B shows text that never existed. With: ACK and event only after commit (`websocket-protocol.md`).
- **Publish in the use case, not the adapter:** without: Bob edits via `PATCH /messages/42`, Alice's open socket keeps the old text. With: one event whichever API made the change (`SendMessageService` pattern).
- **State-carrying events:** without: two quick edits arrive out of order, B keeps the older text. With: `MESSAGE_UPDATED.version`; the client drops a version ≤ the one it holds.
- **Tombstone keeps its seq:** without: client drops the deleted message, sees a seq gap, resyncs. With: `MESSAGE_DELETED{messageId, seq}` marks the slot (03 §9).

## Done when
1. `EDIT {messageId, content, expectedVersion}` → `ACK {messageId, version, editedTime}`; other subscribed connections get `MESSAGE_UPDATED {messageId, seq, createdTime, content, version, editedTime}`; the actor's connection gets none.
2. EDIT stale version → `NACK CONFLICT`; window closed / not sender → `FORBIDDEN`; unknown / non-member → `NOT_FOUND`; no NACK broadcasts; socket stays open.
3. `DELETE {messageId}` → `ACK` + `MESSAGE_DELETED {messageId, seq, createdTime}`.
4. `REACT {messageId, emoji, on}` → `ACK` + `REACTION {messageId, emoji, userId, on}`; bad emoji → `INVALID`; cap → `CONFLICT`.
5. `READ {seq}` (envelope `channelId`) → `ACK {seq: effective}` + `READ_RECEIPT {userId, seq}` to the channel's subscribers.
6. No-ops (same content, re-delete, repeat react/unreact, READ not advancing) → `ACK`, no event.
7. The REST edit/delete/reaction/read endpoints publish the same events (no actor connection to skip).
8. Missing `messageId`/`content`/`seq`/`emoji`/`on` → `NACK INVALID`; v1 sessions receive none of the new events.
- **Out of scope:** receipt ≤ 50-member cap + 2 s throttle (T13), backplane (T07/T08), TYPING (T12), RESUME "changed since" (T09), reply preview in `MESSAGE_NEW` (P5-T05), delete-then-retry `duplicate=true` (T09 note).
- **Tests:** `{Edit,Delete,React,Read}HandlerTest` (command, ACK); service tests (event after commit, none on no-op/exception); `WsMessageEventsIT`: 2 clients for 1–6, REST `PATCH` → WS event (7); negative authz: non-member's 4 frames → `NOT_FOUND`, no event to subscribers.
- **Files:** `handler/v2/{Edit,Delete,React,Read}Handler`, `dto/v2/*Payload`, sealed `domain/chat/model/RealtimeEvent`, `RealtimeEmitterPort`, `SessionEmitterAdapter`, the 4 services + commands (nullable `connectionId`), `MessagePort`/`ReactionPort`/`MemberPort` return values, `ws-protocol` skill.
- **Invariants / authz:** membership stays in the services (P3); events go only to `getConnectionsByChannel` (subscribed members).
