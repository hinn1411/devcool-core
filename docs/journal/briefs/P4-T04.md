# P4-T04 — v2 EDIT/DELETE/REACT/READ frames + live events
P4 · mode B · Should · est 6.5 h · done · 2026-11-27

**Why:** only `SendMessageService` fanned out; edit/delete/reaction/read reached others only on refetch, and v2 NACKed these types `UNSUPPORTED`.
**Value:** protocol v2 → M2; closes P3-T06/T07/T09/T10 deferrals. Unblocks P5-T05/T07/T09 and T07/T08 (events cross the backplane).

## Concepts
- **Commit → publish:** without: an edit broadcasts, the commit fails, B shows text that never existed. With: events only after commit.
- **Publish in the use case:** without: an edit via `PATCH /messages/42` leaves Alice's socket stale. With: one event whichever API made it.
- **State-carrying events:** without: out-of-order edits leave the older text. With: `MESSAGE_UPDATED.version`; the client keeps the highest.
- **Tombstone keeps its seq:** without: a deleted message looks like a seq gap → resync. With: `MESSAGE_DELETED{messageId, seq}` (03 §9).

## Done when
1. `EDIT {messageId, content, expectedVersion}` → `ACK {messageId, version, editedTime}`; other subscribers get `MESSAGE_UPDATED {messageId, seq, createdTime, content, version, editedTime}`; the actor's socket gets none.
2. Stale version → `NACK CONFLICT`; not sender / window closed → `FORBIDDEN`; unknown / non-member → `NOT_FOUND`; no event; socket stays open.
3. `DELETE {messageId}` → `ACK` + `MESSAGE_DELETED {messageId, seq, createdTime}`.
4. `REACT {messageId, emoji, on}` → `ACK` + `REACTION {messageId, emoji, userId, on}`; bad emoji → `INVALID`; cap → `CONFLICT`.
5. `READ {seq}` → `ACK {seq}` (clamped marker) + `READ_RECEIPT {userId, seq}`.
6. No-ops (same content, re-delete, repeat react, READ not advancing) → `ACK`, no event.
7. REST edit/delete/reaction/read publish the same events.
8. Missing `messageId`/`expectedVersion`/`seq`/`emoji`/`on` → `NACK INVALID`; v1 sessions get none of the new events.
- **Out of scope:** receipt cap/throttle and REACT/EDIT/DELETE rate limits (T13), backplane (T07/T08), TYPING (T12), RESUME "changed since" (T09), reply preview in `MESSAGE_NEW` (P5-T05).
- **Tests:** `{Edit,Delete,React,Read}HandlerTest`, `ChannelEventPublisherTest`, the 4 service tests, `SessionEmitterAdapterTest`, `WsMessageEventsIT` (2 clients, REST → WS, non-member → `NOT_FOUND`).
- **Invariants / authz:** membership checked in the services; events go only to `getConnectionsByChannel`.
