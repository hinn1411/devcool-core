# P3-T15 — MARKDOWN message strategy
P3 · mode A · Could · est 1.5h · done · 2026-11-10

**Why:** `ContentType.MARKDOWN` is allowed by the enum (`ContentType.java:5`) and the DB check (`V1__baseline.sql:94`), but has no strategy bean → `strategyFor` throws (`MessageService.java:130-137`) → every markdown send gets an ERROR frame (docs/learning/04 § "Where else this applies"). Also, no send validates content: 1001 chars hits `varchar(1000)` (`V1__baseline.sql:87`) as a raw DB exception, not a `DomainException` (`RawWebSocketHandler.java:107`).
**Value:** phase goal: all 4 content types send. Unblocks P3-T06 (edit is "text/markdown only") and P3-T13 (FTS over content).

## Concepts
- **Server stores source, client renders:** without: the server turns `**hi**` into HTML, so edit, search and any renderer change all have to work through HTML. With: raw `**hi**` is stored and pushed, and `contentType` just tells the client to render it.
- **Sanitize on output, not input:** without: a client renders `[x](javascript:…)` or raw `<img onerror>` → XSS, and server-side stripping misses encodings. With: the renderer disables raw HTML and allowlists link schemes. Read: OWASP XSS cheat sheet § output encoding.
- **Validate in the domain, before the DB:** without: a long markdown message → `DataIntegrityViolationException` → not an ERROR frame, and seq was already bumped (then rolled back). With: the length check runs before authz and the seq bump (like `strategyFor`) → `InvalidMessageConfigException` → ERROR frame, no tx.

## Done when
1. A member sends `MARKDOWN` with `"# hi **x**"`: it gets the next seq, the content is stored byte-for-byte, and ACK + push carry `contentType: "MARKDOWN"`.
2. History returns it with `contentType: MARKDOWN` and the same raw content (no escaping, no stripping).
3. A non-member sending MARKDOWN gets the existing membership error, with no seq bump.
4. TEXT or MARKDOWN with blank content, or more than 1000 characters → `InvalidMessageConfigException`, rejected before any port call. Exactly 1000 is accepted.
- **Out of scope:** rendering/sanitizing (frontend), the startup strategy-coverage check (user: no), edit rules (P3-T06), FTS over markdown syntax (P3-T13).
- **Tests:** `MarkdownMessageCreationStrategyTest` (type + fields); `MessageServiceTest` (markdown seq, non-member, blank/1001/1000 for TEXT and MARKDOWN with `verifyNoInteractions`); `WsSendMessageServiceTest` (push contentType); history mapping already covered by `MessageDtoMapperTest`.
- **Files:** new `application/service/chat/strategy/MarkdownMessageCreationStrategy.java`, `AbstractMessageCreationStrategy` or a text-content check, `MessageService`, the tests.
- **Invariants / authz:** validation → `requireMembership` → replay → bump (`MessageService.java:88-110`). A rejected send never moves `last_seq`.

## Decisions
| Question | Answer | Source |
|---|---|---|
| Server-side sanitize/strip HTML | No: store raw, the client sanitizes on render | user; OWASP output encoding |
| Startup coverage check (all enum values have a strategy) | No, not in this task | user |
| Content validation | TEXT + MARKDOWN: not blank, ≤ 1000 characters (code points, matching PG `varchar(1000)`), no NUL (PG rejects 0x00; added in review), before any port call | user; `V1__baseline.sql:87`; security review |
| Error code | Reuse `InvalidMessageConfigException` (→ ERROR frame / 400) | `MessageService.java:134` |
