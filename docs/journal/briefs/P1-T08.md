# P1-T08 — Refresh cookie scope and bad-token 401
P1 · mode A · Must · est 3.5 h · agreed · 2026-10-02

**Why:** the `rt` cookie has `Path=/api/v1/auth/refresh` (`AuthController.java:129`, `:202`, `:229`), so a browser never sends it to `/refresh_token` or `/logout` (audit #7). A bad token makes `verifyRefresh` return `null` (`TokenIssuerAdapter.java:86`), and `RefreshTokenService.java:38` then throws an NPE → 500.
**Value:** closes audit rows #7 and "+ `verifyRefresh`" → P1 Definition of Done. Unblocks P1-T12 (refresh-cookie IT) and P5's silent-refresh login flow; applies ADR-0011 decision 4.

## Concepts
- **Cookie path is a directory:** without: the SPA calls `/refresh_token`, no cookie is attached, the user is logged out after 1 h. With: `Path=/api/v1/auth` covers both endpoints and nothing else. Read: `learning/02` §9.
- **A port never returns `null`:** without: a tampered token gives an NPE far from the cause and a 500. With: `Optional<TokenSubject>`, and the service must handle the empty case. Read: `learning/04` (`:167`).
- **One answer for every bad token:** without: expired, forged, reused and missing tokens give 500, so the SPA can't tell "log in again" from "server broke". With: all give 401 `AUTH_225`. Read: `11-security.md` §Concepts.
- **Cookie or body, not both:** without: `LoginResponse` carries `refreshToken` in JSON, so any XSS reads what `HttpOnly` hides. With: the token exists only in the cookie. Read: `learning/02` §9.

## Done when
1. Login, refresh, logout and change-password all set `rt` with `Path=/api/v1/auth; HttpOnly; Secure; SameSite=Strict`, built in one helper.
2. Given a forged, expired, wrong-type, malformed, reused or missing refresh token, `/refresh_token` returns 401 `AUTH_225` and writes nothing.
3. Given a missing or malformed `rt`, `/logout` returns 401 `AUTH_225`; logout verifies the token through `TokenIssuerPort`, not `JwtUtils`.
4. `TokenIssuerPort.verifyRefresh` returns `Optional<TokenSubject>`; no Spring Security exception is thrown on the refresh or logout path.
5. The login and refresh JSON bodies contain no `refreshToken` field.
- **Out of scope:** DB round-trip IT (P1-T12, needs P1-T11); reuse detection that revokes the token family (no owner yet); the 14-day JWT vs 7-day cookie/DB lifetime mismatch (`learning/05`, no owner yet); the service's remaining `adapters.out` imports (P1-T13).
- **Tests:** `AuthControllerTest`: `Set-Cookie` attributes on all four endpoints, no `refreshToken` in either body, missing cookie → 401. `RefreshTokenServiceTest`: empty `Optional`, consumed token and null token → `RefreshTokenInvalidException` with no port writes, for refresh and logout. New `TokenIssuerAdapterTest`: forged / expired / access-token-as-refresh / garbage → empty.
- **Files:** `AuthController`, `LoginResponse`, `RefreshTokenResponse`, `AuthDtoMapper`, `TokenIssuerPort`, `TokenIssuerAdapter`, `RefreshTokenService`, the three test classes, phase file checkbox.
- **Invariants / authz:** no token value appears in logs, exception details or response bodies; a rejected refresh consumes and stores nothing.

## Decisions
| Question | Answer | Source |
|---|---|---|
| Who throws | The service; the port returns `Optional` | User, CLAUDE.md "Domain exceptions" |
| Exception class | Existing `RefreshTokenInvalidException`, not a new `InvalidRefreshTokenException` | `HttpErrorMapper.java:25` |
| Cookie attributes | `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth` | ADR-0011 decision 4 |
| Reused / consumed token (`RefreshTokenService.java:41`) | 401 via `RefreshTokenInvalidException`, in this task | User |
| Missing `rt` cookie | Cookie optional in the controller; the service throws → 401 | User |
| Refresh token in the JSON body | Removed from both response DTOs in this task | User, `learning/02` §9 |
| Malformed token on `/logout` | 401, verified through the port | User |
