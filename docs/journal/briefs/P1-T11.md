# P1-T11 — Testcontainers base + Flyway smoke IT
P1 · mode A · Must · est 3 h · done · 2026-10-05

**Why:** `DevCoolApplicationTests.java` has no `@Test`, so it boots nothing (`learning/06` §1). P1-T01's "schema from Flyway alone" was only checked by hand (`briefs/P1-T01.md:21`). There's no `src/test/resources`, so `${JWT_ACCESS_SECRET}` can't resolve in any test context.
**Value:** "Integration tests on a real Postgres" (phase goal) → P1 Definition of Done → M1. Unblocks P1-T12 (first ITs), P1-T14 (CI runs ITs), P3-T03 race IT, P8-T01 pgvector.

## Concepts
- **Singleton container:** without: `@Container` per class → 10 IT classes = 10 container starts on new ports, and each new port forces a new Spring context. With: one container started in a static block, shared by the whole JVM run. Read: `learning/12` §3.
- **Context cache key:** without: one IT adds `@MockitoBean` or its own `properties=` → a second context and another Hikari pool. With: all configuration lives on the base class; subclasses add tests only. Read: `learning/12` §4.
- **Surefire vs Failsafe:** without: the class is named `…Tests` → Docker starts on every `./mvnw test`. With: `*IT` runs only under `./mvnw -Dit verify` (`pom.xml:249`). Read: `learning/12` §2.
- **Profile file vs shadowing:** without: `src/test/resources/application.properties` *replaces* the main one, so `ddl-auto=validate` is silently gone. With: `application-test.properties` is merged on top of it. Read: `learning/12` §4.

## Done when
1. Given Docker is running, when `./mvnw -Dit verify` runs, then `DevCoolApplicationIT` boots the full context with **no env vars** and passes.
2. `flyway_schema_history` starts with versions 1 and 2 and every row succeeded (not "exactly": V3 must not break the smoke test). `ix_message_channel_id_id` exists, and `vector` is in `pg_available_extensions`.
3. `./mvnw test` starts no container and runs no `*IT`.
4. One container declaration serves both `AbstractIntegrationTest` (`@SpringBootTest` + MockMvc) and `AbstractJpaIT` (`@DataJpaTest`). Two IT classes produce one container start and one context per base class.
5. The container has `.withReuse(true)`: off unless `testcontainers.reuse.enable=true` is set in `~/.testcontainers.properties`, and a no-op in CI.
- **Out of scope:** the first real ITs and DB cleanup (P1-T12); running ITs in CI and caching images (P1-T14); `CREATE EXTENSION vector` (P8-T01).
- **Tests:** `DevCoolApplicationIT`: context loads + the 3 SQL checks; run `./mvnw test` to confirm no Docker.
- **Files:** `pom.xml` (3 test dependencies), `src/test/resources/application-test.properties`, `src/test/java/com/devcool/support/*`, `DevCoolApplicationTests.java` → `DevCoolApplicationIT.java`, phase checkbox.
