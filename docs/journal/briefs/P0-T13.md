# P0-T13 — PR auto-review prompt with the repo's rules
P0 · mode C · Should · est 1 h · done · 2026-09-30

**Why:** the auto-review is silently broken, not just generic. `.github/workflows/claude.yml:31-38` passes no `claude_args --allowedTools`, so Claude can't post: PRs #90–#97 have 0 reviews/comments while every run is green (run 36702508979: `permission_denials_count: 1`). The prompt never mentions `CLAUDE.md` or `.claude/rules/`.
**Value:** every PR from P1 on gets a pre-review against the repo's own rules before yours (ref 16: "the Action runs Claude on PRs with the repo's rules as the review brief"). P0's last non-optional task.

## Concepts
- **Allowed tools in headless runs:** without: the prompt says "post a review", `gh pr comment` isn't allowed and no one can approve it → denied, job green, nothing posted. With: `--allowedTools "mcp__github_inline_comment__create_inline_comment,Bash(gh pr comment:*),Bash(gh pr diff:*),Bash(gh pr view:*)"` → comments appear. Read: ref 09 → claude-code-action README.
- **Path-scoped rules don't load from a diff:** without: a PR edits `ChannelService.java`, Claude reads only `gh pr diff` → `hexagonal.md` (`paths: src/main/java/**`) never loads. With: the prompt maps changed paths to the files to read (`src/` → hexagonal + testing; `infra/`, auth/jwt/websocket → `security-reviewer` checklist). Read: ref 16 → Memory and rules.
- **A workflow PR can't test itself:** without: the PR that changes `claude.yml` is the test → the action wants the workflow to match `master`'s, so that run fails or uses the old prompt. With: merge, then prove it on throwaway PRs (confirm during build).

## Done when
1. Given a PR changing `src/main/java/**`, when it gets the `claude-review` label, then Claude posts inline comments, each naming its rule (`CLAUDE.md` PR guideline or `hexagonal.md`).
2. Given a PR changing `infra/**` or auth code, then the comments cover the security checklist (authz in service, cookies, IAM).
3. Given a docs-only PR (`docs/**`), then the auto-review job doesn't run; `@claude` still works.
4. The run log shows `permission_denials_count: 0`.
5. The prompt references the guidelines by path, never copies them; `CLAUDE.md` stays their single source.
- **Out of scope:** the `@claude` job; `ci.yml` path filters (P1-T14).
- **Tests:** YAML parse / `actionlint`; after merge, two throwaway PRs (small `src/` change; `infra/` file) → check comments and run logs, close unmerged.
- **Files:** `.github/workflows/claude.yml`; phase-0 (tick).
- **Invariants:** review job keeps `contents: read`; allowed tools are PR read + comment only; no secrets in the prompt; PR text never interpolated into shell.
