# P2-T08 — deploy.yml, infra-plan.yml, infra-apply.yml
P2 · mode C · Must · est 7 · agreed · 2026-10-20

**Why:** `app` deploys only by hand today (`infra/README.md:48-90`); `ci.yml` has no plan job and nothing applies `infra/**` → M1 ("merge deploys to dev; plan → review → apply") is unmet.
**Value:** P2 → M1. Unblocks P2-T09 (shares the concurrency group, tag lookup and asleep detection; its resume verifies what a hibernated merge registered), P2-T12, and every later deploy (P4 2 tasks, P6 worker).

## Concepts
- **Migrate before rollout:** without: new tasks hit the old schema and N tasks race on Flyway. With: one `ecs,migrate` task exits 0, *then* the service updates; exit ≠ 0 stops the deploy. Read: ref 09 §Concepts, phase 2 §Database migrations.
- **Pipeline owns the image tag:** without: `infra-apply` on `app` rolls the service back to a stale tag. With: plan/apply pass the family's last ACTIVE revision tag; the service ignores `task_definition` (`infra/modules/ecs-service/main.tf:99`). Read: ADR-0003.
- **OIDC sub + protected master:** without: any master-context job (`@claude`) or direct push reaches `gha-deploy`. With: only `environment: aws-deploy` jobs match (`infra/stacks/bootstrap/oidc.tf:73-96`), pinned to the workflow file (#7), and master needs a PR (#1). Read: bootstrap review #1, #7.
- **One concurrency group:** without: deploy + infra-apply both change `app` → lock error or stale revision. With: `concurrency: aws-dev`, no cancel-in-progress, shared with env-power.

## Done when
1. Given a backend merge while awake, then `:<sha>` is in ECR, migrate exits 0, the service is stable on the new revision, and `https://<domain>/actuator/health` = 200.
2. Given a failing migration, then the deploy stops before the service update (running revision unchanged).
3. Given a merge while hibernated (`/devcool/dev/app/*` absent), then the image is pushed and a revision registered with it; nothing wakes; the run summary says "verify on resume".
4. Given a merge while asleep (`sleep`, count 0), then migrate + service update run, smoke is skipped with a notice.
5. Given a PR touching `infra/stacks/<s>/**`, then a plan comment per changed stack; `infra-plan` is a router job in `ci-gate`'s `needs`.
6. Given that PR merged, then changed stacks apply in order network → data → edge → app (`app` with the running tag); a re-plan shows "No changes". While hibernated: network/data apply with toggles off, `app` is skipped.
7. Master ruleset on (PR required, `ci-gate` only check, no bypass); `aws-deploy` admin bypass off — before merging `infra-apply.yml` (#1).
- **Out of scope:** env-power and verify-on-resume (P2-T09), prod (ADR-0013), frontend deploy (P5), README deploy section (P2-T12), bootstrap apply in CI.
- **Tests:** no-op backend commit → green deploy; broken health check → circuit-breaker rollback (once); infra PR → plan comment; direct push to master → rejected; `@claude`/`claude-auto-review` can't assume either role after #7.
- **Files:** `.github/workflows/{deploy,infra-plan,infra-apply,ci,ci-changes}.yml`, `infra/stacks/bootstrap/{state,ecr,oidc}.tf`, `infra/README.md`, phase 2 (T09 carry-over).
- **Invariants:** no AWS keys in GitHub; plan = `gha-plan`, apply/deploy = `gha-deploy`; actions pinned to a SHA; Trivy fails on fixable HIGH/CRITICAL; a merge never wakes the env.
